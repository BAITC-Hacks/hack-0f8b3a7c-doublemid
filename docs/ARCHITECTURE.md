# Архитектура

React + Vinext/Vite, Cloudflare Workers и D1. Приложение содержит два серверных API: `/api/auth` и `/api/workspace`.

## Доступ

В `lib/auth.ts` определены один бизнес-аккаунт и пять учебных команд. Пароли читаются из серверного окружения; публичные учебные значения работают только при включённом демо. Успешный вход создаёт случайный 64-символьный токен, в базе хранится SHA-256 токена. Cookie — HttpOnly, SameSite=Strict, Secure на HTTPS; срок 12 часов. Выход удаляет серверную сессию. Постоянный счётчик попыток ограничивает вход по сочетанию адреса клиента и email: 10 за 15 минут.

`currentAccount` проверяется при каждом чтении/изменении. Только бизнес создаёт, уточняет, публикует задачи и выбирает/подтверждает команды. Только студент отправляет предложения и отчёт по своему выбранному отклику. `teamId` берётся из аккаунта. Фильтрация чужих откликов и личных черновиков происходит на сервере.

## Общие данные

Таблицы `tasks` и `proposals` сохраняют JSON, общий ключ пространства — `sana-shared-v2`. Старые демо-пространства не удаляются и не импортируются автоматически. Стартовые примеры создаются один раз с конфликтобезопасной вставкой. D1 batch объединяет инициализацию. Все операции используют параметризованный SQL.

Изменение задачи проверяет revision и исходный payload, решение/этап — исходный payload. Конфликт отдаёт 409 вместо потери изменений. requestId отклика позволяет безопасно повторить отправку; новая независимая отправка разрешена. Баллы выводятся из принятого состояния каждого отклика, повторное подтверждение не создаёт новое событие начисления.

Последовательность: pending → chosen или rejected; chosen → отчёт → milestone=true. После подтверждения менять решение или отчёт нельзя. Возможно выбрать несколько команд. Автоматическое назначение отсутствует.

Интерфейс получает снимок при входе, затем раз в 15 секунд и при фокусе окна. Незавершённый ввод хранится в sessionStorage, при явном выходе очищается. Подтверждение карточки никогда не восстанавливается из браузерного кэша.

## Ограничения

Один бизнес-аккаунт, пять преднастроенных команд; нет регистрации, восстановления пароля, нескольких организаций и почтовых уведомлений. Один подтверждённый этап на отклик. AI не является обязательным для работы, реальные платные запросы в проверках не выполняются. Проверка полноты — прозрачная эвристика, факты подтверждает бизнес. Для публичного пилота нужны управляемые аккаунты, эксплуатационный мониторинг и ограничения расхода AI.
