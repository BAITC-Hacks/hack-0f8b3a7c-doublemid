# AI Sana — Challenge Hub

MVP команды DoubleMid: бизнес превращает потребность в понятную задачу, студенты выбирают её в общем каталоге, бизнес сравнивает предложения и подтверждает выполненный этап.

## Быстрый запуск

Нужны Node.js 24 и npm. Команды выполняются в папке проекта:

```sh
npm ci
npm run db:migrate
npm run dev
```

Откройте http://localhost:5173 (или адрес из вывода сервера). Миграции можно запускать повторно: применяются только новые. Данные сохраняются в `.wrangler/state` между перезапусками.

Для готовой сборки:

```sh
npm run build
npm start -- --port 4173
```

Откройте http://localhost:4173. Для чистого клона сначала нужны `npm ci` и `npm run db:migrate`. Локальная конфигурация базы — `wrangler.local.jsonc`: её имя намеренно отличается от автоматически загружаемой конфигурации сборщика, чтобы не дублировать DB.

## Аккаунты

На странице входа есть две кнопки для быстрой демонстрации. Также можно войти по email и паролю:

| Кабинет | Email | Демо-пароль |
|---|---|---|
| Бизнес / администратор | admin@sana.demo | AdminSana2026! |
| Студент, команда Qadam | student@sana.demo | StudentSana2026! |
| Дополнительные команды | team2@sana.demo — team5@sana.demo | StudentSana2026! |

Бизнес и студент могут работать из разных браузеров или устройств с одним сервером. Открывайте разные аккаунты в разных профилях/приватных окнах: обычные вкладки одного браузерного профиля разделяют cookie. Общие данные обновляются каждые 15 секунд и при возвращении в окно.

Публичные пароли предназначены для учебного показа. Перед закрытым пилотом задайте в серверном окружении `DEMO_LOGIN_ENABLED=false`, `ADMIN_PASSWORD`, `STUDENT_PASSWORD` и, если нужны, `TEAM2_PASSWORD`–`TEAM5_PASSWORD`. Без заданного пароля соответствующий аккаунт при выключенном демо недоступен. Самостоятельной регистрации и восстановления паролей пока нет.

## Что доработано

- Вместо переключателя ролей — серверный вход, отдельные кабинеты и отзыв сессии при выходе.
- Общая база задач для всех аккаунтов; черновики видит только бизнес. Студент получает только свои предложения, но видит общее число откликов и рейтинг достижений.
- Обзор бизнеса: публикации, черновики, новые отклики, результаты на проверке. Обзор студента: интересные задачи, предложения, работа и баллы.
- Конструктор: свободное описание → минимум 3 уточнения → редактируемая карточка → ручное подтверждение → публикация.
- Рейтинг 0–100, расшифровка, недостающие поля и пересчёт. Каталог сортируется по рейтингу; есть поиск и фильтры темы/готовности.
- Неограниченное число откликов: идея, план, срок и HTTP(S)-ссылка. Команда определяется сессией, а не присланным идентификатором.
- Бизнес сравнивает предложения карточками или таблицей; выбирает одну, несколько или ни одной команды.
- Выбранная команда отправляет отчёт. Только после этого бизнес проверяет и подтверждает результат. +20 баллов один раз за отклик; сам выбор баллов не даёт.
- Адаптивный экран входа, два обзора, рекомендации по интересам и рейтинг команд за подтверждённые результаты.

## Рейтинг

| Показатель | Вес |
|---|---:|
| Контекст и потребность | 20 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Контакт и взаимодействие | 10 |

Контекст/потребность разделены на 10+10, контакт/взаимодействие — на 5+5. Сервер начисляет баллы только за заполненные и подтверждённые поля. От 8 символов, распространённые заглушки не учитываются. Это оценка полноты, не семантическая экспертиза. Предварительный балл в редакторе не является начисленным рейтингом.

0–39 — требует уточнения; 40–69 — рабочая; 70–89 — готовая; 90–100 — приоритетная. Последнее название сохранено из исходного проекта: присланный текст задания обрывается на диапазоне 70–89. Опубликованная карточка доступна для откликов при любом балле. Неподтверждённые личные черновики в общий каталог не попадают.

## Помощник

Без ключей и платных запросов работают контекстные резервные вопросы. Ответы пользователя переносятся в карточку, отсутствующие факты не выдумываются. Для OpenAI скопируйте `.env.example` в `.env.local`, задайте `OPENAI_API_KEY` и включите `OPENAI_REQUESTS_ENABLED=true` только если готовы оплачивать запросы. Модель задаётся `OPENAI_MODEL`; существующая настройка — `gpt-5.4-mini`.

Реальное обращение к OpenAI в этой доработке не выполнялось. Контракт и резервные режимы проверены на имитациях. При недоступности модели конструктор продолжает работать. Контактное поле исключено из AI-запроса; личные сведения в свободном тексте автоматически не удаляются. Подробности — `docs/OPENAI-INTEGRATION.md`.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm run test:built
```

`test:built` запускает собранный Worker с временной D1, применяет обе миграции и проверяет вход, права, общий каталог, скрытые черновики, предложение от своего аккаунта, ручной выбор нескольких команд, отчёт, подтверждение, однократные баллы, конфликт правок, повторы запросов, недопустимые ссылки и выход. Это рекомендуемая безопасная проверка: база пользователя не меняется.

`node scripts/test-api.mjs` предназначен только для отдельного тестового сервера с исходными демо-данными, потому что создаёт и изменяет записи в общем каталоге. Не запускайте его на рабочем показе. `TEST_URL` задаёт адрес сервера.

## Состав

- `app/page.tsx`, `components/hub/` — интерфейс и кабинеты.
- `app/api/auth/route.ts`, `lib/auth.ts` — вход, ограничения попыток, сессии.
- `app/api/workspace/route.ts` — серверная авторизация действий и бизнес-логика.
- `lib/domain.ts` — рейтинг, типы, вопросы и синтетические примеры.
- `db/`, `drizzle/` — D1 и миграции.
- `docs/CRITERIA.md` — соответствие присланному кейсу.
- `docs/CLICK-THROUGH.md` — сценарий для демонстрации.
- `docs/REVIEW-AND-TESTING.md` — проверенные изменения и ограничения.

Архив содержит исходники, миграции и lockfile; не содержит зависимостей, локальной базы и секретов. Изменения не отправлялись в GitHub: доступа к приватному репозиторию в сессии нет. Замените соответствующие файлы в своей рабочей копии, проверьте запуск и сохраните обычным коммитом. Старые записи исходной версии остаются в базе под прежними идентификаторами пространств; новый общий каталог создаётся отдельно и не удаляет их.
