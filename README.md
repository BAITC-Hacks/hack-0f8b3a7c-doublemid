# AI Sana — практические задачи

Работающий учебный MVP по кейсу МНВО — AI Sana. Русскоязычный конструктор задачи, уточняющий помощник, прозрачный рейтинг 0–100, общий каталог, неограниченные отклики и ручной выбор команд.

## Что реализовано

- Деловой реестр задач, поиск, компактные показатели и адаптивная версия для телефона. Фильтры откликов по статусу.
- Восстановление незавершённых карточки и отклика после обновления текущей вкладки; защита ввода от случайного закрытия.
- Свободный черновик, минимум 3 уточняющих вопроса, редактируемая карточка из 9 оцениваемых полей плюс название, организация и тема.
- Подтверждение человеком перед публикацией и пересчётом рейтинга. Изменение любого поля снимает подтверждение.
- Каталог сортируется по убыванию рейтинга. Поиск, фильтры по теме и готовности. Низкий рейтинг не ограничивает просмотр и отклик.
- Переключение учебных ролей «Бизнес» / «Студенческая команда». Пять профилей с интересами и навыками.
- Отклик содержит идею, план, срок и URL прототипа. Бизнес может выбрать несколько команд, отклонить предложения или оставить их без решения.
- Подтверждение фактического этапа с описанием проверенного результата даёт 20 баллов команде. Повторное подтверждение не увеличивает баллы.
- Защита от устаревших правок, конфликтов подтверждения этапа и повторной отправки одного отклика.
- Серверное сохранение в Cloudflare D1. Ошибки сохранения не очищают формы.
- 5 исходных черновиков, 5 карточек с рейтингами 100/85/70/45/20, 5 команд, 5 предложений. Все примеры синтетические, example.com — демонстрационные ссылки.

## Важные границы MVP

Это интерактивная учебная среда для демонстрации, а не многопользовательская производственная платформа. Один браузер получает отдельное рабочее пространство и может переключать все демонстрационные роли. HttpOnly cookie связывает его с серверными записями; после очистки cookie создаётся новое пространство. Между устройствами данные автоматически не синхронизируются. В пределах одного пространства опубликованные задачи доступны всем пяти командам. Перед реальным пилотом нужны отдельная авторизация организаций и команд, права доступа и общий каталог между пользователями.

AI-адаптер использует OpenAI Responses API и модель GPT-5.4 mini при явном включении реальных запросов. Без включения работает локальная заглушка. При ошибке OpenAI, тайм-ауте, отказе или некорректном ответе показываются резервные вопросы с объяснением причины. Пользовательские ответы переносятся в карточку без изменения и без добавления моделью новых фактов. Заголовок по умолчанию — начало черновика, его можно изменить.

Реальный запрос после этой доработки ещё не выполнялся: интеграция проверена на имитациях ответа API. Работоспособность ключа, баланс и доступ к модели пока не подтверждены.

## Запуск

Нужен Node.js 24 и npm. Зависимости фиксируются package-lock.json.

```sh
npm ci
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_keen_iron_lad.sql
npm run dev
```

Откройте адрес, который выведет сервер. Миграцию применяйте один раз к новой локальной базе. Для запуска готовой сборки вместо последней команды используйте `npm start`. Локальная база лежит в `.wrangler/state` и не включается в исходники.

При изменении схемы создайте новую миграцию: `npm run db:generate`. Если ограниченная Windows-среда не может получить имя системного пользователя, используйте `node --require ./scripts/windows-compat.cjs node_modules/drizzle-kit/bin.cjs generate`. На хостинге миграции применяет Sites.

## Настройка OpenAI

Локальный ключ хранится только в `.env.local` под именем `OPENAI_API_KEY`. Файл исключён из Git; не добавляйте его в архивы и не присылайте в чат. Шаблон без секрета — `.env.example`.

```dotenv
OPENAI_API_KEY=
OPENAI_MODEL=gpt-5.4-mini
OPENAI_REQUESTS_ENABLED=false
```

По умолчанию реальные запросы выключены, даже при наличии ключа. После согласования расходов владелец может поставить `OPENAI_REQUESTS_ENABLED=true` и перезапустить dev-сервер. Каждое уточнение тогда отправляет описание и заполненные поля OpenAI; значение отдельного поля контакта исключается. Контакты, случайно включённые в свободный текст, автоматически не удаляются: используйте обезличенные описания.

Один запрос ограничен 12 000 символов входного JSON, 1 800 выходных токенов и ожиданием 15 секунд. Автоматических повторов нет; в одном экземпляре сервера действует пауза 30 секунд между реальными запросами одного учебного пространства. Это не глобальный финансовый лимит и не защита публичного сервиса от злоупотреблений. Перед реальным пилотом нужны надёжная авторизация, постоянные лимиты и согласованный бюджет.

`store:false` отключает сохранение Response как ресурса API; это не обещание нулевого хранения у провайдера. Сборка не должна включать локальные секреты. На размещённом сервере ключ и флаг включения задаются отдельно в хранилище секретов; сайт в этой поставке не опубликован.

## Архитектура

- `app/page.tsx` — интерфейс на React, компоненты Shadcn/Radix, каталог, конструктор, карточка, отклики.
- `app/api/workspace/route.ts` — серверная валидация, расчёт рейтинга и изменения состояния.
- `lib/domain.ts` — типы, шкала, резервные вопросы, промпт, синтетические данные.
- `lib/openai-questions.ts`, `lib/ai-config.ts` — серверный OpenAI-адаптер и конфигурация; `lib/ai-types.ts` — статусы для интерфейса.
- `db/schema.ts`, `db/store.ts`, `drizzle/` — D1, подготовленные запросы, миграции.
- `.openai/hosting.json` — подключение DB к Sites.

Записи задач и предложений привязаны к случайному идентификатору пространства. Все запросы ограничиваются этим идентификатором. POST проверяет Origin при его наличии; cookie имеет HttpOnly и SameSite=Strict, на HTTPS — Secure. Ввод отображается как текст; ссылки прототипов допускают только HTTP(S). Выбор роли — интерфейсная демонстрация, не граница безопасности.

## Формула рейтинга

| Поле | Баллы |
|---|---:|
| Контекст | 10 |
| Потребность | 10 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Контакт | 5 |
| Формат взаимодействия | 5 |

Поле засчитывается при наличии не менее 8 символов после удаления пробелов по краям. Ответы «не знаю», «не указано», «уточняется», «пока нет», «нет данных», «неизвестно» не засчитываются. Это прозрачная эвристика полноты; она не оценивает смысловую достоверность или измеримость показателей. Бизнес подтверждает заполненные сведения; до подтверждения показана только предварительная оценка. Сервер пересчитывает итог самостоятельно и не принимает присланный клиентом балл.

Уровни: 0–39 требует уточнения; 40–69 рабочая; 70–89 готовая; 90–100 приоритетная. Для одинакового балла более новая карточка идёт выше. Черновики до ручной публикации доступны во вкладке «Мои задачи»; опубликованная карточка с низким баллом видна всем демонстрационным командам.

## AI-контракт

Промпт хранится в `AI_PROMPT` в `lib/domain.ts`; правила работы помощника описаны в интерфейсе. Вход — пользовательский черновик, тема и текущие поля. Ответ:

```json
{"questions":[{"key":"data","text":"Какие данные доступны команде?"},{"key":"success","text":"По каким показателям вы примете результат?"},{"key":"limits","text":"Какие сроки и ограничения нужно учитывать?"}]}
```

`parseAIOutput` проверяет JSON, 3–12 вопросов, известные уникальные ключи и длину текста. Некорректный ответ заменяется резервными вопросами, исходный ввод сохраняется. Когда все поля заполнены, задаются 3 проверочных вопроса. В обработчике `questions` уже подключён серверный адаптер Responses API с JSON Schema. Он принимает только завершённые ответы, проверяет ключи полей и структуру; отказ и неполный ответ не считаются успешной генерацией. Модель не получает полномочий изменить данные, рейтинг или решение бизнеса. Автоматический выбор команд не предусмотрен.

## Проверки

```sh
npx tsc --noEmit
node scripts/test-domain.mjs
node --test scripts/test-openai.mjs scripts/test-reliability.mjs
# Если локальный ключ настроен и сборка выполнена:
node scripts/check-secret-boundary.mjs
# При запущенном локальном сервере на http://localhost:4173:
node scripts/test-api.mjs
# После сборки: готовый Worker + клиентские файлы + API на временной базе
node scripts/test-built.mjs
```

`TEST_URL` позволяет задать другой локальный адрес. API-регрессия требует `OPENAI_REQUESTS_ENABLED=false` и откажется работать с включёнными платными запросами. 17 имитационных тестов AI проверяют контракт запроса, отключённый режим, отсутствие ключа, 401/403, квоту и частоту, тайм-ауты, сетевые сбои, отказы, незавершённые и некорректные ответы. Ключ не выводится в тестах. API-тест создаёт отдельное пространство с тестовыми записями и не изменяет пространство пользователя. Ещё 9 автоматических проверок покрывают размер и формат запросов и безопасное восстановление карточки и отклика. Расширенный API-тест проверяет повторные запросы и одновременные изменения.

Проверено: веса и границы рейтинга; минимум три вопроса; некорректный AI-ответ; запрет публикации без подтверждения; публикация с 10 баллами; отклик при низкой готовности; ручной выбор и отклонение; этап и повторное подтверждение; рост рейтинга до 45; сохранение после повторного чтения; изоляция пространств; запрет javascript: URL. В браузере проверены каталог, фильтр по низкой готовности и WebMCP-инструмент с допустимым и недопустимым вводом.

## Демонстрация за 5 минут

1. **0:00–0:40** В роли бизнеса нажмите «Создать задачу», выберите пример «Сервис» и «Уточнить задачу».
2. **0:40–2:00** Добавьте пользователей, данные, результат и критерии успеха. Покажите рост предварительного рейтинга справа.
3. **2:00–2:45** Соберите карточку, задайте название и организацию. Отредактируйте при необходимости, подтвердите сведения и опубликуйте.
4. **2:45–3:40** Переключитесь на студенческую команду. Найдите задачу, отправьте идею, план, срок и демонстрационную HTTPS-ссылку.
5. **3:40–4:30** Вернитесь в роль бизнеса, откройте отклики и вручную выберите команду.
6. **4:30–5:00** В рамках учебного примера подтвердите проверенный этап, опишите результат, покажите 20 баллов команды. Объясните, что в реальной работе подтверждение даётся только после фактической проверки.

## Отдельный платный smoke-test

Только после явного разрешения владельца на один платный запрос:

```sh
node scripts/test-live-ai.mjs --allow-paid-request
```

Скрипт отправляет один короткий синтетический кейс, не меняет флаг включения приложения и не повторяет запрос. Без флага он завершается без обращения к OpenAI. Выводит только вопросы и безопасный статус.

Официальные контракты: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [GPT-5.4 mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini).
